## 실행

Python 3.12 이상에서 프로젝트 폴더를 열고:

```powershell
Copy-Item .env.example .env
# .env에 공공데이터 키와 Codyssey 키를 입력
powershell -ExecutionPolicy Bypass -File .\start.ps1
```

현재 작업 환경은 별도 `work/app.env`를 APP_ENV_FILE로 연결했습니다. 개인 키는 배포용 압축에 포함하지 않습니다. 프로젝트 자체에 실제 키를 복사하지 않았습니다.

## 바뀐 추천 구조

1. **기본 문답 5개:** 나이, 주민등록 읍면, 필요한 도움, 가장 필요한 도움, 가구.
2. **후보 검색:** 청양군/충남 공통/중앙·공공기관 사업을 모읍니다. 중앙기관 사업이라는 이유로 실제 시행지역이 전국이라고 확정하지 않습니다. 제목의 청년·아동 단어만으로 일괄 제외하지 않습니다.
3. **LLM 정책 분석:** Codyssey `gpt-5.4-mini`가 대상, 선정기준, 혜택 금액·주기·기간·본인부담, 신청경로, 접수기간을 추출합니다. AND/OR 조건식과 원문 필드·인용을 반환합니다.
4. **서버 검증:** 인용이 원문에 존재하는지, 숫자·금액·날짜가 인용에 있는지, 필드·값이 허용되는지 확인합니다. 근거가 없으면 미확인으로 낮춥니다. 논리식은 서버가 충족/미충족/미확인의 3값으로 평가합니다.
5. **중복 검토:** 같은 이름·기관·지역의 사업은 기본 연결하고, 다른 이름의 유사 사업은 LLM이 원문을 비교합니다. 같은 사업, 추가지원, 별개, 불확실로 나눕니다. 지역이 다른 사업은 자동 합치지 않습니다. 각 출처의 원문과 ID를 모두 보존합니다. 조건 충돌은 별도로 표시합니다.
6. **맞춤 설명:** 사용자가 동의한 경우에만 상황 정보를 Codyssey에 보내 서버의 조건 판정과 원문에 근거한 설명을 받습니다. LLM이 서버의 상태를 바꾸거나 선정확률을 만들 수 없습니다. 동의하지 않아도 공개 정책 분석과 서버 조건 비교로 이용할 수 있습니다.
7. **추가 문답:** 이번 후보의 미확인 조건에서 질문을 고릅니다. 질문마다 영향을 받는 후보 수를 안내하고 최대 3개씩 제시합니다. 이미 ‘모르겠다’고 답한 항목은 다시 묻지 않습니다. OR 조건에서 다른 가지가 충족되면 불필요한 질문을 하지 않습니다. ‘신청 방법 맞춤 안내’에서는 방문·온라인 가능 여부를 별도로 입력할 수 있습니다.
8. **결과:** 확인한 주요 조건 / 더 확인할 조건 / 신청 도움 필요 / 이미 수급 중 / 현재 조건 불일치로 구분합니다. ‘주요 조건이 맞음’은 전체 자격이나 선정 확정이 아닙니다. 해석하지 못한 세부 기준은 그대로 표시합니다. 기초연금을 받는다고 답한 경우 해당 사업을 신규 추천과 분리합니다.

### 추천 순서

확인된 주요 조건이 맞는 후보와 미확인 후보를 구분한 뒤, 각 목록에서 가장 필요한 분야를 먼저 안내합니다. 같은 주기의 현금 지원 중 **원문에서 검증한 금액끼리만** 비교합니다. 월 지원과 일회 지원, 현금과 돌봄을 임의로 환산하지 않습니다. 대출 원금도 현금 지원금과 비교하지 않습니다. 금액이 없으면 0원으로 취급하지 않습니다. 동률은 지역 관련성과 이름으로 정렬합니다.

선정확률·임의의 적합도 점수·신청 편의성 가중치는 없습니다. 모르는 조건의 개수가 많다는 이유로 추천점수를 깎지 않습니다. 어르신 화면에는 가중치 슬라이더가 없습니다.

### 신청 경로

방문이 어려우면 방문 경로를 ‘현재 어려움’으로 표시하고 온라인·전화·자동 적용 등 다른 공식 경로를 안내합니다. 온라인 사용 불가도 동일합니다. 대리신청은 허용 여부·대리인이 확인되지 않으면 이용 가능으로 단정하지 않습니다. 신청 장벽은 자격과 순위를 바꾸지 않습니다.

### 검색 범위와 AI 한계

전체 공공 데이터를 매 문답마다 LLM에 보내지 않습니다. 이번 필요 분야·어르신 관련성에 따라 원문 18개를 우선 검토하며, 더 보기로 36/48개까지 확대합니다. 전체 후보 수와 이번 검토 수를 화면에 구분합니다. 검색 단계의 누락·모델의 의미 해석 오류가 가능하며 완전한 자격 판정이나 완전한 중복 제거를 보장하지 않습니다. 원문 인용의 존재 검증은 의미의 정확성을 보장하지 않습니다.

소형모델의 계획된 역할(정책 조건 추출·중복 후보 비교·사용자 상황에 따른 설명)은 현재 LLM이 대신합니다. 소형모델 가중치를 학습한 것은 아닙니다. LLM 교체 지점은 `llm.py`, 조건 분석은 `analysis.py`, 판정·경로·순위는 `engine.py`입니다.

## 데이터 수집·갱신

```powershell
powershell -ExecutionPolicy Bypass -File .\refresh.ps1
```

- 정부24 목록·지원조건, 중앙부처 복지 목록, 충남 지자체 목록을 수집합니다. 정부24 목록의 상세 설명을 사용합니다.
- 출처별 마지막 성공 시각과 실패 여부를 보존합니다. 일부 실패 시 기존 데이터와 실패 표시를 유지합니다.
- 상세 캐시는 목록 수정일과 비교하여 바뀌거나 이전 형식인 항목을 다시 수집합니다. 캐시에 수집 시각을 기록합니다.
- API 호출 한도를 고려해 상세 요청에 일일 예산을 둡니다. 기본 중앙부처 20 / 지자체 90회분을 예약하며 재시도 최대 3회분을 미리 차감합니다. 이 앱 외부에서 사용한 호출은 알 수 없습니다. 미갱신 상세는 최신 검증으로 간주하면 안 됩니다.
- 서버가 켜져 있으면 24시간이 지난 스냅샷을 자동 갱신합니다. 서버가 꺼져 있으면 작동하지 않습니다. AUTO_REFRESH=0으로 비활성화할 수 있습니다.
- 정책 원문·모델·프롬프트가 바뀌면 AI 분석 캐시 키가 바뀝니다. 공개 정책 분석만 `data/analysis.sqlite3`에 저장합니다.

공개 정책을 미리 분석하려면:

```powershell
.\.venv\Scripts\python.exe warm_analysis.py --limit 48
# --limit 0 은 전체 후보 분석. 토큰과 시간이 많이 소요될 수 있습니다.
```

## 개인정보와 작업 처리

상황 정보·대화 원문은 브라우저 메모리에서 유지하며 새로고침하면 제거됩니다. 서버는 추천 작업과 결과를 메모리에서 처리하고 15분 뒤 정리합니다. 작업 ID는 추측하기 어려운 난수이며 API 응답은 캐시하지 않습니다. 개인 맞춤 결과·사용자 답변은 SQLite나 정책 파일에 저장하지 않습니다. 저장한 공개 정책 ID만 기기 localStorage에 남깁니다.

AI 자유입력 전송과 상황 정보 기반 AI 설명은 각각 동의가 필요합니다. 원문 정책 분석은 공개 정보만 사용합니다. 초기화 시 진행 중인 작업 기록도 삭제하고 이후 개인화 요청을 중단합니다. 이미 외부로 전송한 요청을 소급 취소할 수는 없습니다.
